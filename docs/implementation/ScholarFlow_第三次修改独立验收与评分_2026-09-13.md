## 尚需修复

### T01 / P1：小数量的相等容差过宽

位置：`skills/literature-evidence-extraction/scripts/quote_audit.py:365`。

独立实跑：源文 1 nL、抽取 2 nL，strict 门禁放行。统一换算成 L 后两者差 1e-9，当前容差 `1e-9 * max(1, |a|, |b|)` 将其视为相等。该公式给小值设置了过大的绝对容差，不能代表测量精度。

要求：区分解析/换算浮点误差与实验允许误差；采用十进制定点/Decimal 或量纲、精度约束下的比较。验收同时覆盖 nL/ng/nm、零与极小非零、正确跨单位换算。不能为了提高匹配率默认允许科学上不同的值相等。

### T02 / P1：单位倍率和千分比换算错误

位置：同文件 `:201`、`:357–358`。

- 源文 5 bp、抽取 5 kb 被放行：bp/kb/mb 被放入同一 factor=1 的组。
- 比例字段源文 0.05、抽取 5‰ 被放行；正确的源文 0.005、抽取 5‰ 却被拒绝。percent 和 permille 都除以 100。

要求：单位表分别声明正确倍率，避免含义不明确的大小写符号；‰ 应按 1000 转换。每个转换规则必须有正反例，不能只验证同单位同数值。

### T03 / P1：未知单位仍退化为无单位数字

位置：同文件 `:289`，`extract_quantities()`。

源文 `5 Gy`、抽取 `5 Sv`，抽取 token 变为 `5`，strict 放行。原因是单位不在表中时 dimension=None，与真正无单位数值没有区分；含数字就能提取，因此“含数字但完全解析失败”的门禁不会挡住这个情况。

要求：区分无单位、未知单位和部分解析。显式数量中的未知单位保留原始 token 并进入待核验，不能静默删除；只有字段明确允许无量纲/计数时才按相应契约比较。不必立即支持所有单位，但不支持必须诚实阻断。

### T04 / P1：检查点封存报版本冲突前已经覆盖检查点

位置：`shared/execution/session_store.py:361–362`。

独立实跑：已有 WAITING_USER 检查点，用过期 expected_revision 封存 CLOSED；调用抛 RevisionConflict，但 checkpoint.json 的 state 已是 CLOSED。因为先写检查点，再调用会检查 revision 的 save_snapshot。

要求：冲突验证在任何写入前完成；检查点与快照要有一致的提交/恢复协议，避免只改写入顺序就把失败窗口转移到另一文件。验收：过期 revision 失败前后两个文件均不变；模拟写入中断后能识别未完成提交。

### T05 / P2：零事件检查点跳过后续全部事件

位置：`shared/execution/session_store.py:392`。

独立实跑：空日志封存 WAITING_USER → 追加 E1 设置 CLOSED → 保存正确快照；一致性检查的重放却停在 WAITING_USER，last_event_id=null。原因是检查点 last_event_id 为 None 时，将 tail 取为 `events[len(events):]`。

要求：零事件检查点应从事件索引 0 开始重放；优先用已核验的 event_count 决定边界，并检查 count、last_event_id、前缀摘要的一致性。增加空会话启动再首次追加的正例。

## 检查点信任边界仍需说明

`seal_checkpoint()` 允许把事件从未定义的字段记录为 inherited_fields 并封存。实跑可将未进入日志的 UNLOGGED idea 封存后报告 consistent=true。

这可以作为明确授权的历史状态导入设计，但不能表述为“所有业务状态纯由事件证明”。建议将首次初始化/历史导入与日常封存分开：导入须记录来源及确认；已有检查点之后不得通过重新封存无审计地接纳新业务字段。当前本报告不把这种有显式继承标记的设计直接等同于伪造，而是要求讲清并落实信任边界。
