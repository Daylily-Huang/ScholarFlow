# Context Resolution Layer: Relevance Filter & Cross-Domain Isolation

> **Status**: Production Standard  
> **Applicability**: Preventing irrelevant or cross-disciplinary historical context from polluting current tasks

---

## 1. 为什么必须执行相关性过滤？

若一个项目工作区中曾存放过不同学科或不同子课题的文档（例如此前存在生态学调查资料，而当前用户正在请求“检索大语言模型长文本评测”）：
- **灾难模式**：Agent 扫描整个工作区，把生态学中的“样带”、“PCR引物”或“物种名”当成本次任务的前提条件，甚至错误加载生命科学透镜；
- **规范模式**：Context Resolver 在采纳任何项目历史文档前，必须先行计算其与当前任务的**语义与领域契合度 (Task-Context Relevance)**。

---

## 2. 三级相关性判定门槛 (The 3-Tier Threshold)

```text
┌──────────────┬─────────────────────────────────────────────────────────────┐
│ HIGH         │ 与当前任务核心实体、研究目标或方法高度匹配 (Score >= 0.75)   │
│              │ -> 自动提取并纳入决策状态 (RESOLVED_FROM_CONTEXT)            │
├──────────────┼─────────────────────────────────────────────────────────────┤
│ MEDIUM       │ 与当前任务存在部分交叉或属于上位背景 (0.40 <= Score < 0.75)  │
│              │ -> 不自动决策；在 Stage 0 简报中作为背景提示，供用户参考      │
├──────────────┼─────────────────────────────────────────────────────────────┤
│ LOW          │ 属于完全不同领域、无关课题或无关历史日志 (Score < 0.40)      │
│              │ -> 物理拦截并彻底忽略，严禁污染当前任务上下文                │
└──────────────┴─────────────────────────────────────────────────────────────┘
```

---

## 3. 领域正交隔离铁律 (Disciplinary Orthogonality Guard)

当检测到当前任务的自然语言描述（如包含“Transformer”、“神经网络”、“算法复杂度”）与工作区中历史文档的学科领域（如“野外调查”、“野生动物”）属于正交异质领域时：
1. **彻底阻断历史领域注入**：严禁将历史领域的特有假定（如取样季节、PCR 体系）带入当前任务；
2. **重置学科透镜**：仅依据当前任务提示词独立执行 Domain Detection，加载契合当前任务的全新透镜。
