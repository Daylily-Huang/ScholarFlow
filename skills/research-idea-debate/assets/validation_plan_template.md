# 最小验证方案模板 (Validation Plan Template)

> 使用时机：会话至少一次进入 P3 之后，需要把命题变成可检验安排时填写。
> **未进入 P3 时不得使用本模板**——此时命题还没有可观察预测，写出来的方案必然是空转。

---

## 一、方案针对的对象

| 项 | 值 |
|---|---|
| idea_id / version | |
| 命题（逐字） | |
| 成熟度 | TESTABLE（必要时 DEVELOPING + 说明理由） |
| 方案作者 | USER / AI建议（须经用户确认） |

## 二、要区分什么

| 编号 | 解释 | 来源 | 若成立应观察到 | 若不成立应观察到 |

> 只列一个解释时不构成"验证"；至少要有第二个可区分的解释或零假设。

## 四、改判条件（必须明确）

| 结果 | 对 H1 的影响 | 对 H2 的影响 | 对命题的影响 |
|---|---|---|---|
| 观察到 …… | 支持 / 削弱 | | |
| 观察到 …… | | | |

> `change_condition` 是必填项。写不出改判条件的设计不是判别设计。

## 五、资源与边界核对

| 项 | 内容 |
|---|---|
| 用户已声明的资源与时间窗 | `[USER]` |
| 本方案是否超出 | 否 / 是（写明超出部分，标"超出已知资源"，需用户决定） |
| 是否涉及跨生长季 | 是 / 否 |
| 是否涉及新增长期投入 | 是 / 否 |

> 超出用户已声明边界时，必须标"超出已知资源"并询问，**不默认可行**。
