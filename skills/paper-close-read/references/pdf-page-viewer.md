# PDF 原页窗口

阅读页支持随时对照**原 PDF 渲染的真实文件页**。优先准备整篇原页；长文体积过大时可明确范围，只嵌入所需页，窗口会显示已内嵌页数。不要用重新排版的原文段落、译文或AI重画冒充PDF原页，也不要把原刊印刷页码直接当PDF文件页码。

## 准备与绑定

若有本地原 PDF，可用可选 PyMuPDF 生成原页：

```text
python scripts/prepare_pdf_pages.py reading-data/original.pdf reading-data
```

默认全部页、140 DPI。可用 `--pages 1,3,7` 或 `--dpi 180`（支持72–240）；已存在原页清单/图片会停止，保留用户核对记录。渲染后将 `source-pdf-pages.json` 的内容原样加入 `fulltext.source_pdf`，再用通用构建器重建。原件只读，不覆盖原PDF或已有HTML；准备失败后检查已产生的中间件再重试。核心HTML构建只需标准库，PyMuPDF只是准备原页的一种可选途径；也可用其他可用PDF渲染器并填写相同契约。

```json
{"file":"original.pdf", "sha256":"原PDF的SHA256", "page_count":9,
 "pages":[{"page":1,"src":"pdf-pages/page-001.jpg","sha256":"此页图像SHA256"}]}
```

所有路径相对 `asset_root`，原PDF和原页图片都需可回查。构建核验原件及图片哈希、文件页范围和重复页码；若图清单也核对了PDF，其文件身份须一致。原页图像嵌入单文件HTML，同一页只在配置中存一份，各段按钮复用，离线不请求外部PDF或CDN。体积随页数和分辨率增长，不能靠删掉用户需要对照的结果页来追求小文件。

## 段落定位与窗口操作

- `source.pdf_page` 有可靠核对记录（`status:verified`、`verification_note`）且该页已准备时，段落右上角显示“查看 PDF 原页”，直接打开该页；原图也可使用独立图清单中已经核实的实际PDF文件页。
- 尚未核实段落页码时显示“浏览 PDF 原文”，允许自行翻页对照，窗口明确提示未核实；不能猜位置或用某个默认页冒充定位正确。没有原PDF/原页素材时保留普通阅读功能，不显示无效按钮。
- 工具栏可打开原PDF浏览。窗口可拖动标题栏、拖拽右下角调整大小、最大化/还原；页码选择、上一页/下一页、适应宽度和缩放均可用。窗口为非模态，可挪到旁边与HTML对照。
- 标题栏可聚焦后用方向键移动，缩放手柄可用方向键调整；Shift加大步长。Esc或关闭按钮收起窗口，并返回触发按钮。移动、缩放或翻页不更改阅读进度和批注。
- “原图放大”窗口也支持拖动及调整大小。窗口大小、图像缩放是两回事：拖窗口改变可用面积，缩放控件改变页内图像大小。

页面为原PDF的栅格快照，保留排版与图表，清晰度取决于生成DPI；不是可选择文字的原生PDF阅读器。原PDF权限、文字提取、来源页码核对独立处理。对外分发含整页图片的HTML需遵循论文许可；不能因为技能MIT便推断私有论文原页可公开。本功能不把原页附加到双语PDF中，避免重复输出整篇原件。

## 实测

在真实浏览器用鼠标拖动、缩放，检查窗口留在视口内、页图内容与对应PDF文件页一致、页码切换和清晰度、关闭后回到原阅读位置。至少实际测试有可靠页码与无可靠页码两种入口。移动/390px模拟布局检查不替代真实手机硬件测试；修改输入或通用资源后重建，不补最终HTML。
