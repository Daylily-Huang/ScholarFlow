# 可编辑科研 PPT

当前版本为 **v1.7.1**。使用前运行 `python scripts/verify_release.py` 核验包完整性；维护或发布时另运行 `python scripts/verify_publication.py` 检查设计契约与隐私边界。具体能力和限制以下文与输入约定为准。

内置厚实版作为稳定设计基线，并提供**自适应资料模式（`visual_mode: adaptive`）**：当 `demo: false` 时自动去除生硬的默认生态位图与卡片内冗余大图标，释放完整卡片宽度，按用户学科资料实时匹配极简线框图标或嵌入原图，并执行严格的字体、字号与位置对齐检查。

涉及接单、输入诊断、已有稿件修改或交付时，读取 [制作与交付](references/authoring-and-handoff.md)。生成前可运行 `python scripts/preflight.py --input INPUT.json`，它不会写入PPT，也不替代原图、图表与视觉验收。交付前运行 `inspect_deck.py` 核对对象、外链及隐私提示；需要整理可交付目录时用 `prepare_handoff.py`，实际预览必须与同一份PPT的哈希对应。

本地安装、升级或回退时读取[安装维护](references/local-installation.md)，只操作明确指定的技能目录，先核验源包并保留旧版。

## 接单与选模板

1. 按顺序确认：**场景 → 配色 → 填充风格**。先问学术分享（`academic`）、课程作业（`coursework`）或实验进展（`progress`）；收到答复后问主配色 P1 蓝白朱红、P2 松绿米白、P3 石墨青金、P4 酒红灰蓝、P5 靛紫芥黄、P6 湖蓝珊瑚、P7 赭橙米白、P8 深蓝香槟金、P9 孔雀青白、P10 黑白朱红；再问“轻盈浅底（`light`）”还是“厚实实底（`solid`）”。已明确的选项沿用，不重复询问；用户明确委托自行选择时默认 `P1 + solid`。
2. 梳理用户提供的论文、数据表、图片或汇报素材，提炼核心科学问题、实验设计与关键数据证据。基于真实材料组织内容，缺失处如实标注，不编造数据。
3. 先列“每页论点 → 证据/文字 → 讲解顺序 → 版式/变体”，覆盖文献核心问题、方法细节和主要结果，不为了图多而删掉必要文字。示例仅供字段与布局参考，不是成稿范式；再从 `assets/template-system.json` 选择匹配的版式（`L1`–`L23`，变化用 `variant`），避免机械套用全部版式。

## 联网素材与解释性动画（v1.4）

- 美化素材先查随包的**在线来源离线素材库**（`assets/media-library/gallery.html` 与 `scripts/assets.py search`），选不到相关素材再联网补充；不能未查询就用自绘图代替。库内487项原SVG、332项已测原生形状及112项生态监测与遗传研究主题见 [素材库与原生形状](references/asset-library.md)。主题可选，不改变通用学科默认值。美化素材优先 **网上可编辑矢量 → 网上高清图片 → 自行绘制或 AI 生成**。优先统一系列、清晰且许可可用的学科素材；找不到合适来源或无法联网时说明后使用后备方案。素材不能替代相关论文原图。
- 涉及图标、辅助插图、SVG、视频或HTML时，读取 [联网素材与解释性动画](references/media-and-animation.md)，执行来源/许可记录、编辑边界、实际播放和离线交付检查。矢量转原生形状需验证，图片与视频内部不宣称PPT可编辑。
- 难解释的机制、反馈、时序等按需增加解释性动画：简单过程优先原生形状＋PPT动画；连续运动可由SVG/HTML渲染成视频内嵌，交付源文件与静态备用。需要交互时另附离线HTML，默认不依赖加载项。不得把示意尺寸、运动速度或循环当成实测数据或生理时间。
- 原生素材插入：在静态稿上用 `scripts/assets.py insert` 按预留插槽或明确坐标插入已验证的原生组合，保留源稿、比例、原色和来源；来源素材不是论文证据图。不能转换的SVG按图片后备，不宣称内部可编辑。
- 能力分层：联网搜索由Agent使用可用工具完成；`generate.py`仍生成静态PPT且普通图片输入为PNG，不自动执行SVG/HTML动画。Windows桌面PowerPoint可用时，另用 `scripts/add_media.ps1` 加原生点击动画与内嵌MP4，再用 `scripts/audit_media.py` 检查媒体记录与视频字节。

## 实时适配资料与去 AI 味原则（重要）

### 真实资料原图硬指标

**提供或选用的论文有相关图表时，正式成稿必须含直接从论文裁取的完整原图；默认不重绘、不整合重组。** 每篇主要证据论文均核对清单与原图落点。缺原文、缺裁图或无法核对时阻止正式生成；不得以自绘图或生成图替代过关。正式输入必须声明 `materials.papers`，无论文才可用空列表。

制作前读取 [原图、变体与整套节奏](references/evidence-and-composition.md)，按其中硬指标、裁图工具和组件约定执行。

- 梳理材料时先列出可用的论文原图、用户结果图、流程图、点位图和表格；与本页论点直接相关、清晰可读的关键证据图优先采用，不用示意插画替代已有的实测证据，也不为了装饰堆图。
- 原图适合保留作者的分析结果、方法结构或地理信息；只有用户明确要求重新组织或改绘，并拿到源数据核对后才另做原生可编辑图表，同时保留原图对照。没有源数据时，不凭截图猜测或补造数值。
- 保留纵横比、原始颜色、坐标、单位、图例和必要统计标注。实测图片默认 `duotone: false`，不得用主题滤镜改变承载含义的颜色。去除空白可裁切；局部放大须标明范围，不隐去改变结论的上下文。
- 密集图表通过拆页、局部放大或调整图文比例提高可读性，不把整张论文页面缩成小图。论文表格保留完整原表；读不清时另加局部放大。用户明确要求转成原生表格时，逐项核对数据并保留原表。
- 论文图片在邻近正文/现有标签中简注“作者、年份、图号”；每页 `sources` 记录对应图片插槽、完整文献/DOI或链接及裁切、改绘情况。用户自己的结果记录数据文件、分析版本或日期；来源不清楚时标注“待核实”，不捏造引用。`sources` 写入备注；L15–L18 与 `original_figure` 变体通过 `figures.caption/source` 自动生成独立可编辑页内图注。旧版式可用 `components` 放置图号、图注与来源，不能只留备注。
- 目前生成器直接接收 PNG；PDF、SVG 等须先导出为清晰 PNG 并核对。原图仍是可移动、缩放、替换的独立图片，内部文字与曲线不宣称可编辑；其余标题、正文和自制图表、框图保持原生可编辑。

选择顺序是“相关性与证据忠实 → 可读性 → 编辑需求 → 视觉统一”。真实来源与忠实呈现提高可核查性，图片本身不构成研究结论可靠的证明。

1. **根据用户资料实时改进视觉元素，拒绝模板硬塞**：
   - **禁止强塞无关插画**：`demo: false` 默认启用 `adaptive` 模式，自动移除模板自带的森林/鸟类位图。若用户资料包含关键原图（如序列比对截图、实验装置、电泳图、地图），可通过单页 `"image": "path/to/fig.png"` 原比例无损嵌入（不强制套双色调滤镜）；若无外部配图，`L5`（封面）、`L7`（章节页）、`L9`（对照页）、`L14`（讨论页）会自动生成**100% 原生可编辑的摘要卡、章节路线图、对照状态卡与讨论落点卡**。
   - **去除生硬“人机感”大图标，实时匹配学科线框图标**：`adaptive` 模式已清理卡片正文区占宽 35%–60% 的重复大图标（`L1/L2/L6/L8/L12/L13/L14`），仅在标题栏与流程节点保留精致极简线框矢量图标。支持在 JSON 中直接指定或由生成器根据文本实时推断学科图标：`dna`（基因/引物/位点）、`pcr`（扩增/分池/实验体系）、`table`（台账/矩阵/表）、`chart`（统计/分布/效能）、`filter`（初筛/过滤）、`warning`（异常/冲突）、`check`（检验/复核/HWE）、`location`（采样/生境）、`layers`（分层/数据）、`workflow`（流程/衔接）、`document`、`compass`、`search` 或 `none`（不显示图标）。
   - **动态章节与原生表格自适应**：`L7` 支持 `active: 0..3` 动态高亮当前章节；`L4` 表格自动按列内容视觉长度分配列宽、统一全部数据格字号为 `20px` 并清除模板残留红底；`L10` 散点图默认不强加回归趋势线（需拟合线时设 `trendline: true`）。
2. **去除 AI 味道（自然学术表达）**：
   - **禁止全篇机械使用 `四字词｜后半句` 标题公式**：标题应直接、自然地概括当页核心发现、方法设计或讨论问题（如“跨物种微卫星引物两阶段筛选流程”、“11个多态位点的遗传多样性与 HWE 检验”），不要每页都硬切四字前缀加竖线。
   - **禁止电报式四字碎词**：自适应模式已将卡片正文区拓宽至 `344–816px`，请写出自然、完整、信息密度合理的学术短句，不要为了迁就旧模板窄框而把句子砍成生硬的口号碎片。
3. **不要有过重的防御**：
   - 聚焦于把论文/项目的**研究背景、技术路线、核心数据、实验细节与可复用启示**讲清楚。
   - **严禁花 2–3 页篇幅反复说教“读法建议 / 本文没有做什么 / 不主张什么 / 证据边界免责声明”**。方法适用条件或样本局限只需结合具体数据在 1 页内客观陈述，不要用防御性套话喧宾夺主。

## 已批准紧凑版式（v1.6）

紧凑版限定为六个经过验收的结构，按三类内容组织：L21 大图与解释（`sidebar`、`journal`），L22 标准化比较（`fraction`、`metrics`、`pipeline`），L23 阶段任务（`lanes`）。选择这些结构时先读 [紧凑版式](references/compact-layouts.md)，从 `assets/examples/compact-approved.json` 取对应字段，不把合成示例当成用户研究结果。

紧凑版标题 **36px（27pt）**、正文 **20–21px**、图表标注 **≥17px**，边距32px；保留已批准的大图面积和对象位置。不得用旧版42px标题规则覆盖这些变体；旧版式维持既有比例。十配色均可选浅底/实底，原图硬指标和联网素材优先顺序不变。

## 制作与排版规范

相对于本 SKILL 所在目录运行命令。先看 [输入与维护约定](references/input-and-templates.md)，仅从 `assets/examples/` 借用所需字段与页面结构，按逐页规划组装 JSON，不照搬示例整套顺序。新输入显式写 `fill_style: light|solid` 与 `demo: false`。

- 旧版 L1–L20 的厚实版按 1280×720 画布：内容页标题 `42px`（31.5pt），正文与卡片优先 `21–25px`（15.75–18.75pt），辅助说明与图表标注 `≥17px`，页脚 `14px`。左右内容边距 `32px`，内容对齐同一纵线。
- 表格表头 `21px` 加粗，数据单元格统一 `20px`，按列宽保持单行或整洁对齐，严禁同一张表内出现 `32px` 与 `23px` 混排或单格折成 3 行导致表格纵向撑破。
- 标题、正文、自制框图、连接线和新增标注保持原生 PowerPoint 对象；仅有原始数据时生成的图表可编辑。嵌入的论文原图/原表内部不宣称可编辑，不能为了可编辑而擅自改绘。
- 配图必须先查 `assets/template-system.json` 的 `image_slots`：`L2/L5/L7/L8/L14` 可用单张 `image`；`L9` 必须用命名 `images`，L15–L18 使用 `figures`；L2/L3/L4/L8/L9/L10/L11 可选择 `variant: original_figure` 放完整原图。其余旧版式没有普通配图插槽。PNG 作为独立图片可移动、缩放和替换，其内部文字不宣称可编辑。
- `L5.highlights` 显式输入仅允许 1–4 项；过长须改写或拆页。自动概览只取最多四个章节/内容标题，不截断标题、数值或来源；它不代表全文摘要。自适应表格超过当前版式容量时拆页，不缩小字号硬塞。

```console
python scripts/check_environment.py
python scripts/generate.py --input INPUT.json --output OUTPUT.pptx --force
python scripts/audit.py OUTPUT.pptx --strict
```

## 内容与视觉分别验收

- 先核对研究重点、数值、条件和来源，再核对视觉。不能以改善内容为由退回粗糙框图、小字和空泛卡片；也不能为美观省略关键解释。
- 保持已认可的标题/正文字号、32px左右边距、主次比例、图片边界与图注位置；重要证据用大图，比较才分栏。使用选定填充风格，红色用于少量关键方向/差异，不整页撒色。
- 同一结构可以合理复用；避免连续三页相同卡片堆叠，不强制每页版式不同。不要逐页机械添加takeaway横幅、数字概括标题或大导航。章节、目录和导航使用同一份章节数据，交付前核对编号、标题与高亮一致。

## 强制检查与交付（必做：原图、字体、字号、位置对齐）

先逐篇核对材料清单与成稿中的完整原图；原图必须来自指定 PDF 页，相关面板、坐标、图例和必要说明完整，来源可追溯。**原图硬指标未满足即不通过，排版再美观也不能交付为正式成稿。** 再按整套缩略图检查主次比例、图注位置和连续页面节奏。

**做完后务必执行严格检查，未通过结构与视觉双重核验不得交付：**

1. **自动化排版与字体/字号/位置审计（必须 0 Error、0 Warning）**：
   运行 `python scripts/audit.py OUTPUT.pptx --strict`，逐项确认：
   - **字体一致**：全篇仅使用当前字体配置（默认 `Noto Sans CJK SC` / `Noto Serif CJK SC`，或 `--font-profile office` 下的 `Microsoft YaHei` / `SimSun`），无未知回退字体。
   - **字号层级与表格字号统一**：无小于 `13px` 的残留碎字；每页字号层级收敛；所有表格的数据行字号 100% 统一（`20px`）。
   - **位置对齐与零碰撞溢出**：无文本框折行溢出（`text_overflow`）、无表格单元格折行撑高碰撞下方说明文字（`table_below_collision`）、无文字与图片/形状边界重叠（`text_overlap` / `text_pic_collision`）。
2. **PowerPoint 实机渲染与目视核验**：
   Windows 环境有 PowerPoint 时运行：
   ```console
   powershell -ExecutionPolicy Bypass -File scripts/render_powerpoint.ps1 -Source OUTPUT.pptx -OutputDir PREVIEW_DIR
   ```
   两个检查脚本均须退出码为 0。检查 `powerpoint-validation.json` 的 `quality_ok: true`（`overflows`、`table_issues`、`font_issues` 全为空），并**逐页查看导出的 `slide-*.png` 预览图**，亲眼核对：
   - 标题、卡片正文、表格与图例的**字体、字号**是否协调统一；
   - 图标与文字、表格与脚注、环形标签与色块、坐标轴与刻度**位置是否对齐、有无压线或重叠**。
   发现任何微小拥挤或错位，立即回改 JSON 或版式参数并重新生成与复检。

静态审计使用排版估算，不能证明所有图表内部、复杂形状和新字体都没有重叠。没有可用的 PowerPoint 渲染环境时，只交付标明“视觉未验证”的待审稿，不宣称跨软件像素一致。

涉及外部素材或动画时，另执行媒体清单核验、实际播放/交互、编辑保存重开和静态备用检查，具体见 [媒体验收](references/media-and-animation.md#溯源记录与交付检查)。静态审计通过不证明动画播放或许可合规；不把未验证的平台写成已支持。
