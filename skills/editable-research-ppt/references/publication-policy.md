# 通用发布与设计契约

公开包使用通用学科场景，不固定本机项目、人员、文件路径、研究结果或个人使用经历。生态、实验、工程等示例只是合成内容；不能据此把任一学科设为全局默认。

## 不能随清洗改变的设计标准

`design-contract.json`冻结三种场景、十套配色、两种填充、L1–L23及其变体、字体、旧版/紧凑版两套字号、32px边距、图表字号下限、原图规则和整套节奏。它另记录关键生成/审计代码和模板结构指纹。Office作者字段或示例文字的清洗不改变图形几何、样式、字体与图表结构。

```console
python -I -S -B scripts/verify_release.py
python -I -S -B scripts/verify_publication.py
python -I -S -B -m unittest discover -s tests -v
```

完整性清单证明文件一致，设计契约另防止把改变后的颜色、字号或版式重新算哈希后当成“没有漂移”。确需改变设计时，必须作为单独设计变更列出差异、提供预览并验收，不能在隐私清洗中顺手更新基线。

## 代码检查与人工检查的边界

| 要求 | 自动检查 | 仍需核对 |
|---|---|---|
| 场景、配色、填充、版式及字段 | 输入校验与冻结契约 | 使用者选择及内容适配 |
| 字体、字号、边界、表格容量、图表数据 | 严格审计与回归测试 | 实机渲染、字形与视觉拥挤 |
| 完整论文原图 | 材料清单、来源、裁图/嵌入字节、过滤与裁切检查 | 清单完整性、图表完整性和科学含义 |
| 主次比例、图片边界、图注、整套节奏 | 配置与部分位置检查 | 逐页和整套缩略图目检 |
| 原生可编辑性 | 对象结构与缓存哈希 | 目标软件改色、移动、保存重开 |
| 联网素材优先、相关性和许可 | 素材来源记录、文件哈希 | 实际搜索、语义、许可条件与页内署名 |
| 隐私 | 文件名、文本、Office XML及内嵌工作簿扫描 | 图片目检、未知形式的敏感内容 |

发布前用同一份候选生成清单、跑测试、看实际预览，再做独立发布核验。核验通过后只提交指定技能及必要CI文件；不夹带输出目录、私人资料、备份或其他模块的未提交修改。发布后核对远端提交与CI结果，不把本地测试通过写成远端CI通过。
