# 日常制作与交付

## 从用户已有信息开始

先识别新建、改稿、图片复刻还是仅导出。改稿沿用用户最新文件，不用模板覆盖；图片复刻先分清原生重建部分和保留图片部分。明确的选项不再问。新建时依次补齐场景、配色和填充风格；补问已有材料、受众、讲解时长、交付平台仅限会改变制作方案的信息。用户委托自行决定时采用已知偏好或P1厚实底，说明假设。

不是每个任务都需要完整问卷。十分钟组会和四十五分钟课程不能使用同一内容密度；用户没有时长时先做逐页论证计划，必要时再问，不凭时长公式删掉研究重点。

## 输入预检

生成前运行只读诊断：

```console
python scripts/preflight.py --input INPUT.json
```

输出为JSON，每条包含`level/path/code/message`。`slides[3].sources`指输入数组第4页的来源字段。修复error再继续；warning是需要检查的提示，例如连续三页同版式，合理重复可以保留。不要为消除节奏提示而无意义换版式。

预检只覆盖输入容器、选项、旧版式必要字段、章节一致性与普通PNG路径。完整论文图和图表正确性仍由生成器与后续审计核对，结构预检通过不代表图表、许可或视觉通过。

L6目录与L7章节页从同一章节数组生成。L6的`chapters`是包含`title`的对象数组；L7的`chapters`是这些标题组成的字符串数组；`active`为0到3的整数，`section`为对应的两位编号，`lines[0]`为当前章节标题。现有目录/章节模板有四项容量，不能宣称任意章节数已自适应。章节页不是强制要求；短报告可以省略，不能留错编号。

## 保存和改稿

生成器先完成内存构建，再暂存完整字节并发布。默认不覆盖；`--force`仅在明确允许替换时使用。保存失败时旧文件保持原样。文件被PowerPoint锁定、磁盘空间不足或文件系统不支持排他硬链接时，应保留原稿并报告错误，不静默退回会覆盖用户文件的保存方式。临时暂存文件位于输出同目录以保证同卷发布，正常成功/失败都会清理；进程被强制终止可能留下点号开头的`.tmp`，确认没有运行中的生成任务后才清理。

改现有PPT时先存新文件；保留页序、用户修改和已有动画，除非本次明确要求调整。不要承诺JSON重新生成会保留在PowerPoint里手改的内容。需要后续重复生成的修改必须同步源输入或模板，交付时说明维护入口。

## 交付给实际使用者

交付第一入口是PPTX，预览来自实际渲染而非生图。已有论文图保持原图，来源就近可读；改绘/示意明确标注。讲者备注写讲解提示，证据与详细出处单独标识；面向公开受众导出前检查备注中的私有路径和未公开资料。不得自动删证据或擅自公开附件。

按任务需要附源JSON、必要素材、简短编辑说明和实际验证记录。需要PDF/PNG时只声明真正生成过的文件。重建的普通文字/框图/图表与独立图片/视频分别说明编辑方式。用户不需要阅读内部实现脚本。新配色、多语言或平台字体变化后要重看实际预览。

交付状态分为：输入待补、已生成但视觉未验、已实机检查。只有证据充足时写最后一种。不得用自动审计绿灯代替内容核对、看图或目标平台测试。


## 对象、离线与交付检查工具

```console
python scripts/inspect_deck.py talk.pptx --require-offline
python scripts/prepare_handoff.py --pptx talk.pptx --output-directory delivery-new --preview-directory actual-preview
```

`inspect_deck.py`按展示顺序统计原生文字/形状/图表/表格/图片，检查内部关系、外部内容依赖及备注/元信息中的路径和凭据模式。报告不复制备注原文或外链目标。`possible_image_only_page`只是整页图片提示；对象结构不证明编辑体验，也不输出“百分之百可编辑”等比例。超链接与外链媒体区分，超链接不阻止离线放映。

`prepare_handoff.py`不覆盖现有文件夹。结构严格检查或离线内容依赖不通过时阻止打包；合法超链接保留。普通本地交付可以带隐私提示，`--public`会阻止检测到的路径/凭据提示，但这个选项既不发布文件，也不证明隐私或许可已完整核查。工具不会擅自删除来源或备注。

默认交付`presentation.pptx`、对象清单、结构报告、编辑说明和文件哈希清单；提供预览目录时，要求本次PowerPoint日志的`source_sha256`与PPT完全相同、`source_unchanged`和`quality_ok`为true，逐页PNG名称/顺序/字节哈希匹配才复制。旧日志未绑定哈希需重新渲染，不能靠改名复用。检查证明的是证据与文件一致，报告不是数字签名，也不证明人工看图已完成。未提供预览则明确写“视觉未验证”。

私有论文、制作JSON和原数据不自动复制进交付包。用户需要复现源项目时按[可搬迁源项目](source-project.md)使用`export_project.py`交付所选输入、资产和冻结运行时；不能把缺少资产的JSON称为可复现项目。公开素材许可、图片中文字、学术内容与目标软件的实机编辑仍需独立完成。

自适应原生后备图标新增camera/tree/leaf/calendar/database。显式选择的语义优先，不为去重换成无关图标；未指定时按附近文字匹配。优先联网选材的规则继续适用，原生图标用于现有图标系统或无合适在线素材的后备，不替代论文原图。


## 双语、长标题与字体环境

正文自适应模式支持`title_translation`：主标题保留42px等既定字号，在其上方放17px原生可编辑的副标题。主标题与副标题各限一行，并按实际标题框宽度校验；英文不再机械套38字符限制。放不下时精炼标题，把条件/解释放正文或备注；不自动缩字号。L5封面继续用`subtitle`，L7章节和L14结束页继续用`lines`，不支持该字段。legacy示例不改变。

双语正文按信息块配对而非逐字堆双行：短术语可以“采集记录 · Records”；较长中英解释使用L2等宽文字区域、L16证据讲解或拆页。L1环形右上说明区不能塞入任意两行中英文字；原生表格也不能靠缩字或多行撑破既定行高。保留原文数值、图例与来源，必要时在图外附译注，不改论文原图内部文字。

```console
python scripts/check_environment.py --font-profile office
```

环境诊断分别报告随包字体哈希、所选字体是否在系统清单中被发现，以及PowerPoint/LibreOffice的注册或命令线索。检测不到字体、没有渲染软件，不等于便携生成失败；尚未探测时标记unverified。检测到应用不证明能启动、编辑或播放，只有实际运行才作为验收。不会自动安装字体、启动Office或修改系统配置。

`render_powerpoint.ps1 -EditProbe`现在也适用于无原生图表的页面：测试文字与位置保存重开；仅在存在原生图表时测试工作簿，并记录`chart_probe_applicable`。无图表不能写成“图表数据修改通过”。

三场景双语输入与实机样板见 [双语样板](../examples/bilingual/README.md)。

需要超出固定槽位的推导链或不等宽原图讲解时，读取[内容驱动原生排版](native-composition.md)。它沿用L15–L18与原图硬指标，支持原生文字、基本形状和完整图片，不通过私有运行时补丁绕过正式生成器。

## 平台与验收范围

| 能力 | 实现与当前验证范围 |
| --- | --- |
| 静态生成、预检、包审计、源项目、安装 | Python≥3.10标准库；本轮Windows Python 3.12实测。跨系统源码路径处理有回归，但未把源码可运行等同于跨软件显示一致。 |
| 字体与显示 | portable配置需要随包Noto字体另行安装；office配置需要目标机有微软雅黑/宋体。字体文件哈希不证明已安装或覆盖所有字符。 |
| 实际渲染和编辑重开 | 本轮Windows桌面PowerPoint 16实测。WPS、LibreOffice、macOS/网页PowerPoint的新版本视觉及编辑体验未实机验证。 |
| 动画与内嵌视频 | 可选Windows PowerPoint后处理，沿用媒体流程；不属于静态源项目重建范围。其它播放器不自动视为已支持。 |

交付前按收件人的目标平台复核。没有目标平台实测时如实说明，不作像素一致、所有字体可用、任意第三方素材可商用或绝无故障的承诺。
